# Web UI 与移动端设计

## 1. 设计目标

当前 Web 控制台采用“桌面音乐客户端”而不是传统后台系统的视觉结构。桌面和移动端共享后端状态、模板和业务 JS，只在布局与交互方式上分层。

## 2. 桌面布局

桌面端主要结构：

```text
左侧导航 | 主工作区 | 播放队列
                    
            底部全局播放器
```

主要页面：播放、音乐库、音乐账号、系统状态、设置。

## 3. 移动端布局

断点：

```css
@media (max-width: 820px)
```

移动端结构：

```text
顶部应用/上下文栏
        ↓
单主视图
        ↓
迷你播放器
        ↓
底部导航
```

底部导航固定为：

- 播放
- 音乐库
- 账号
- 更多

“更多”承载系统状态和设置，避免在小屏底部塞入过多一级导航项。

## 4. 播放页移动交互

### 服务器和频道

服务器选择、频道选择仍复用桌面 DOM 和原有业务状态；移动端只改变布局。服务器选择浮层在窄屏转换为底部 Sheet。

### 搜索

搜索框、平台选择和结果列表在移动端改为单列歌曲列表。操作按钮应保证触控区域接近或大于 44×44 CSS px。

### 队列

桌面右栏在移动端变成 Bottom Sheet。继续复用原有队列 DOM，因此刷新、删除、清空和“顶歌”不维护第二份状态。

### 播放器

同一个 `#player-container` 在移动端拥有两种形态：

1. 迷你播放器：当前歌曲 + 高频控制 + 队列入口。
2. 展开播放器：封面占位、歌曲信息、进度、循环、播放/暂停、跳过、停止、队列。

不要新增另一套播放器状态对象。

## 5. 主题

支持：

- 深色
- 浅色
- 跟随系统

偏好保存在：

```text
kook.ui.theme
```

`theme-init.js` 在共享应用壳中尽早应用主题，并设置 Bootstrap `data-bs-theme`、原生 `color-scheme` 和移动浏览器 `theme-color`。

浅色主题不是简单 invert，而使用冷灰白背景、白色 Surface、深色文字和同一紫色品牌色。

## 6. 其他浏览器端偏好

- `kook.ui.density`：comfortable / compact
- `kook.ui.reducedMotion`：减少动画

这些设置只影响当前浏览器，不写入服务端 `.env`。

## 7. 前端文件职责

| 文件 | 职责 |
|---|---|
| `style.css` | 历史/通用样式和 Bootstrap 兼容 |
| `app.css` | 新应用壳与共享页面组件 |
| `dashboard.css` | 播放页主要桌面布局 |
| `theme.css` | 浅色/深色主题覆盖 |
| `mobile.css` | 移动端布局与触控优化 |
| `app-ui.js` | UI 偏好、主题应用、系统健康灯 |
| `theme-init.js` | 尽早加载主题/移动端资源并减少页面跳闪 |
| `mobile-ui.js` | 移动导航、Sheet、展开播放器、移动视口行为 |
| `dashboard.js` | 播放页核心业务 |
| `dashboard-ui.js` | 非核心桌面增强和队列顶歌 UI |

## 8. 移动端适配原则

- 不新增 `mobile.html`。
- 不复制搜索/播放/账号 API 调用逻辑。
- 不用 CSS 缩放整页来“适配”。
- 优先使用 Bottom Sheet、单栏、可横滑 Tab 和固定底部控制。
- 必须考虑 `env(safe-area-inset-*)`。
- 必须考虑软键盘导致的 Visual Viewport 变化。
- 触控控件优先 44px 级命中区域。
- 弹层打开时应控制背景滚动和 Escape/点击外部关闭。

## 9. 推荐真机回归尺寸

至少覆盖：

- 375×667
- 390×844
- 393×852
- 430×932
- 768×1024（平板窄屏边界）

还应测试横屏、浏览器地址栏收起/展开、软键盘、深浅色切换和 iOS 安全区。
