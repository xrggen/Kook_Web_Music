# 打包、发布与 env 历史清理

本流程适用于本项目在此 Windows 主机上的打包、Cloud/Edge 发布与验收收尾。在采用 VibeCoding 共享环境的主机上，执行前读取共享正文 `env/configs/workflows/post-release-env-cleanup.md`。

## 1. 明确交付与范围

记录提交、工作区未提交修改、平台与部署角色，确认当前交付路径和授权范围。当前代码、历史 Git worktree、其他会话的小程序/图标工作不能当 env 垃圾删除。

## 2. 打包与验证

复用共享环境中的兼容依赖；仅在缺少所需版本时按全局规则安装。临时脚本和验证结果放在 `env/codex_temp-script` 的任务专属子目录。

按变更执行必要测试与平台同步检查，再保存当前交付及非敏感的校验/验收结论到项目规定位置。打包排除真实凭据、认证配置、Cookie、运行数据库和可能含凭据的日志；清理授权不允许读取、扫描、复制或归档这些保护项。

## 3. 发布与验收（仅当任务包含发布）

GitHub 发布先审计拟提交索引和新引入的历史，推送开发分支并验证，再按授权合并主线。GitHub 源码发布与服务部署或微信平台发版各有独立的验收入口。

按 [单机部署](deployment.md) 或 [Cloud / Edge 部署](cloud-edge-deployment.md) 操作。验收至少覆盖本次改动涉及的服务与功能，Cloud/Edge 任务核验实际运行角色和连接状态。发布失败或仍在排错时保留必要的非敏感材料，问题解决后继续下一阶段。

本流程不授权额外发布、凭据迁移或修改认证配置。

## 4. env 历史清理（末尾必做）

- [ ] 确认当前交付已经验证；仅打包任务在打包验证后进入此阶段。
- [ ] 读取共享流程，确定本会话允许范围与保留集；同项目会话协调避免交叉删除。
- [ ] 检查本项目在 `env/codex_temp-script`、`env/projects` 的历史项及已登记版本。按名称先排除凭据/认证目录，保留在途工作、运行目录、共享依赖和最小回滚集。
- [ ] 删除前核对规范化绝对路径严格位于 env 内，沿途和目标没有链接，没有进程、文件或当前流程引用。只执行精确清单。
- [ ] 仅处理已确认无用的非敏感具体文件；父目录含 token、认证库或受保护日志时保留父目录。不得为删除父目录而移动保护项。
- [ ] 名称含 key/pem/secret/token/auth/credential 的 ACL、权限备份、CLIXML、SDDL 同样排除，不得读取内容来判断是否可删。保护跳过项、枚举错误和无法确认的内容向父目录传递“不可递归删除”状态。
- [ ] 默认逐文件执行非敏感允许清单，完成后只移除真正为空的目录。不能忽略跳过项后递归删除其父目录；历史清理脚本不能不经复核当作当前流程入口重跑。
- [ ] 如涉及已登记版本，先重读库存并仅合并本项目非敏感记录；不得覆盖其他会话的条目。
- [ ] 复查当前入口、交付、共享依赖及必须保留的目录，保存路径/文件数/逻辑大小和保留理由。
- [ ] 在最终回执及 handoff 写明实际结果；无可清理项也须明确记录，不清理其他项目凑数。

GitHub 的 `platform-sync.yml` 是测试 CI，不接触本机 env。上述人工发布收尾阶段由本机负责交付的会话执行，不向 CI 添加清空共享目录的步骤。
